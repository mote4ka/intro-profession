# Практика 1: репозитории и интеграции

Учебный проект: поиск фильма в OMDb API, получение JSON и вывод основных полей.

## Запуск

Нужен Python 3.10 или новее и ключ [OMDb API](https://www.omdbapi.com/apikey.aspx).

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Откройте `rest_api_demo.ipynb` в VS Code с расширениями Python и Jupyter.
Выберите ядро `.venv`, перезапустите его и выполните ячейки сверху вниз.
В текущей ветке `env-feature` скопируйте `.env.example` в `.env`, если файла ещё нет,
и заполните `OMDB_API_KEY`. Если `.env` уже заполнен, не перезаписывайте его.
Запускайте ноутбук из корня проекта. Название фильма вводится с клавиатуры;
ключ читается из `.env` (переменная окружения имеет приоритет) и не выводится.
В `master` ключ запрашивается через скрытый ввод `getpass`.

## Проверки

```bash
python -m unittest discover -s tests -v
python scripts/check_live.py
```

Первая команда выполняет 12 изолированных тестов без сети и настоящих ключей.
Вторая делает три реальных запроса к OMDb и требует заполненный `.env`.
Проверяются существующий фильм, отсутствующее название и заведомо неверный ключ.
В `master` этих проверок и библиотеки `python-dotenv` нет: они добавлены в `env-feature`.
Результаты ревью описаны в `REVIEW.md`.

## Как устроен запрос

Отправляем GET-запрос по HTTPS на `https://www.omdbapi.com/` с параметрами
`t` (название) и `apikey` (ключ). `raise_for_status()` проверяет HTTP-статус,
`response.json()` преобразует JSON в словарь Python. Поля извлекаются через `.get()`.
Описание параметров: [официальная документация OMDb](https://www.omdbapi.com/#parameters).

Параметр `t` возвращает одну запись, а не список всех одноимённых фильмов.
Для уточнения можно передать год в параметре `y` или IMDb ID в `i`.
Для списка совпадений API предлагает отдельный параметр `s`.

## Ветки и история

- `master`: учебный вариант с ручным вводом ключа.
- `movie-output-feature`: добавление актёров и краткого описания; вливается в `master`.
- `env-feature`: чтение ключа из `.env` и исправления после ревью; остаётся отдельно.

Посмотреть историю: `git log --graph --oneline --all`.
Переключить вариант: `git switch master` или `git switch env-feature`.
`.env` и `.venv` исключены из Git ещё до первого коммита.

## Сдача

Публикацию пользователь выполняет самостоятельно в GitHub. В методичке указан
GitVerse; допустимость замены платформы нужно согласовать с преподавателем.
После создания пустого удалённого репозитория выполните из этой папки:

```bash
git remote add origin <URL-вашего-репозитория>
git push -u origin master
git push origin movie-output-feature env-feature
```

Не добавляйте `.env` принудительно через `git add -f` и не публикуйте окружение.
Перед публикацией проверьте выводы ноутбука и `git status`.
Файл `reflection1.md` содержит черновик рефлексии для личной редакции.
Проверка через GigaCode и действия в OnlineTestPad выполняются пользователем:
здесь нет доступа к этим сервисам, и их прохождение не имитируется.
